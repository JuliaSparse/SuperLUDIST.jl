Usage

All SuperLUDIST.jl programs run under MPI. Every rank runs the same script, and calls into SuperLU_DIST are collective: every rank in the grid must make them, in the same order.

Process grids

SuperLUDIST distributes the factorization over a 2D nprow × npcol grid of MPI ranks, which must use at most `MPI.Commsize(comm)ranks. The index type of the grid (Int32orInt64`) selects which SuperLU_DIST build is used, and must match the index type of the matrices:

using MPI, SuperLUDIST
using SuperLUDIST: Grid
MPI.Init()
grid = Grid{Int64}(2, 2, MPI.COMM_WORLD)
grid.iam # this rank's number within the grid

By default the ranks are laid out on the grid in row-major order. With batch = true the grid is built with superlu_gridmap instead, from a usermap matrix of ranks (row-major by default), for example to give each of several grids its own subset of ranks:

grid = Grid{Int64}(2, 2, MPI.COMM_WORLD; batch = true, usermap = [0 1; 2 3])

Replicated matrices

A ReplicatedSuperMatrix holds the whole matrix in compressed sparse column form on every rank, and is solved with SuperLUDIST's `pgssvxABglobal` drivers. This is the simplest way to get started, but it needs the whole matrix and right-hand side on every rank.

using SparseArrays
A = ReplicatedSuperMatrix(S, grid)                # S::SparseMatrixCSC, the same on every rank
x, F = SuperLUDIST.pgssvx!(A, copy(b))            # b holds every row

A ReplicatedSuperMatrix can also be built from any SparseBase store, with 1-based indices or 0-based CIndex ones, for example from coordinate (COO) form:

using SparseBase
I, J, V = findnz(S)
A = ReplicatedSuperMatrix(SparseBase.CoordinateStore((Int64.(I), Int64.(J)), V, size(S)), grid)

To read a Matrix Market file on one rank and broadcast it:

using MatrixMarket
A = MatrixMarket.mmread(ReplicatedSuperMatrix{Float64, Int64}, "matrix.mtx", grid)
Note

Because of a bug in SuperLUDIST ([xiaoyeli/superludist#238](https://github.com/xiaoyeli/superlu_dist/issues/238)), Float32 solves of a ReplicatedSuperMatrix on more than one rank are done without equilibration (options.Equil is set to NO). Use a DistributedSuperMatrix if you need it.

Distributed matrices

A DistributedSuperMatrix holds a contiguous block of rows on each rank, in compressed sparse row form, and is solved with SuperLU_DIST's pgssvx drivers. Each rank also holds its own rows of the right-hand side.

If each rank builds its own rows, wrap them directly (CSR arrays with 1-based indices):

A = DistributedSuperMatrix(rowptr, colidx, nzval, firstrow, localsize, globalsize, grid)

Here firstrow is the global number of this rank's first row, localsize the size of the local block ((number of local rows, number of columns)) and globalsize the size of the whole matrix. The same block can be given in coordinate form, with local row numbers:

A = DistributedSuperMatrix((rows, cols), nzval, firstrow, localsize, globalsize, grid)

Or scatter a matrix assembled on one rank:

using SparseBase
using SparseBase.Communication: distribute_evenly, scatterstore!
csr = grid.iam == 0 ? convert(SparseBase.CSRStore, SuperLUDIST.coostore(Float64, Int64, S)) : nothing
chunks = grid.iam == 0 ? distribute_evenly(size(S, 1), 4) : nothing
A = scatterstore!(DistributedSuperMatrix{Float64, Int64}(grid), csr, chunks; root = 0)
rows = A.first_row:(A.first_row + SparseBase.Communication.localsize(A, 1) - 1)

MatrixMarket.mmread(DistributedSuperMatrix{Tv, Ti}, filename, grid) reads a file on the root rank and distributes its rows the same way.

3D process grids

For large problems on many ranks, SuperLUDIST's communication-avoiding 3D algorithm can be much faster than the 2D one. A Grid3D arranges nprow × npcol × npdep ranks as npdep layers of nprow × npcol 2D grids. SuperLUDIST partitions the elimination tree between the layers, so that each layer factorizes its own subtrees independently, and replicates the top of the tree, trading some extra memory for much less communication. See Sao, Li and Vuduc (2019) and the SuperLU_DIST documentation for when this pays off.

A DistributedSuperMatrix on a Grid3D is solved with SuperLUDIST's pgssvx3d drivers, with the same functions as on a 2D grid. Its rows must be distributed over all the ranks of the 3D grid, so `MPI.Commsize(comm)should benprow * npcol * npdep`:

using SuperLUDIST: Grid3D
nprocs = MPI.Comm_size(MPI.COMM_WORLD)                 # say 8
grid = Grid3D{Int64}(2, 2, 2, MPI.COMM_WORLD)          # 2 layers of 2 × 2 grids
grid.zscp.Iam                                          # this rank's layer

csr = grid.iam == 0 ? convert(SparseBase.CSRStore, SuperLUDIST.coostore(Float64, Int64, S)) : nothing
chunks = grid.iam == 0 ? distribute_evenly(size(S, 1), nprocs) : nothing
A = scatterstore!(DistributedSuperMatrix{Float64, Int64}(grid), csr, chunks; root = 0)
rows = A.first_row:(A.first_row + SparseBase.Communication.localsize(A, 1) - 1)

x, F = SuperLUDIST.pgssvx!(A, b[rows, :])               # factorize and solve
y = F \ b[rows, :]                                      # reuse the factorization

MatrixMarket.mmread(DistributedSuperMatrix{Tv, Ti}, filename, grid) also works with a Grid3D. examples/pdrive3d.jl is a complete example, the counterpart of SuperLU_DIST's EXAMPLE/pddrive3d.c.

Things to know about the 3D drivers:

  • npdep must be a power of two.
  • There are no 3D drivers for replicated matrices.
  • pgssvx3d sets up how the right-hand sides are moved between the layers when it factorizes, for the number of right-hand sides it is given then (at least one), and every later solve must use the same number. SuperLUDIST.jl therefore solves a different number of right-hand sides in blocks of that size, so F \ B works for any B. If you will solve many right-hand sides at once, factorize with that many.
  • The parallel symbolic factorization (ParSymbFact = YES) and the ParMETIS ordering (ColPerm = PARMETIS) are not supported with npdep > 1. The defaults use neither.
  • PStatPrint prints the statistics of the first layer, as SuperLU_DIST's 3D examples do.

Solving and reusing factorizations

pgssvx! factorizes and solves in one call, overwriting b with the solution, and returns the solution and a factorization object:

x, F = SuperLUDIST.pgssvx!(A, b)

You can also factorize first with lu!, and then solve with \ or ldiv!, as often as needed and with any number of right-hand sides:

using LinearAlgebra
F = lu!(A)
x = F \ b
ldiv!(F, B)   # in place

To factorize without a right-hand side, call pgssvx! without b:

_, F = SuperLUDIST.pgssvx!(A)
SuperLUDIST.isfactored(F) # true

Note that SuperLU_DIST may scale and permute the values of A in place.

Options

Options wraps SuperLUDIST's `superludistoptionst`. It starts from SuperLU_DIST's defaults, and any field can be set with a keyword or as a property:

using SuperLUDIST: Options, Common
opts = Options{Int64}(; ColPerm = Common.MMD_AT_PLUS_A, PrintStat = Common.NO)
opts.IterRefine = Common.NOREFINE
x, F = SuperLUDIST.pgssvx!(A, b; options = opts)

The enum values (Common.YES, Common.NO, Common.METIS_AT_PLUS_A, …) are in SuperLUDIST.Common. With PrintStat = YES (the default), statistics are printed after each solve, and SuperLUDIST.PStatPrint(F) prints them again. PStatPrint is collective.

Test problems

mmread_and_generatesolution reads a Matrix Market file and generates a known solution and matching right-hand sides, as SuperLUDIST's own example drivers do, and [`infnormerrordist](@ref) prints the error of a computed solution. [GenXtruedist!](@ref) and [FillRHSdist!`](@ref) are the underlying pieces.

coo, b, xtrue = SuperLUDIST.mmread_and_generatesolution(Float64, Int64, 1, "matrix.mtx", grid)

Examples

The examples directory has complete scripts:

mpiexecjl -n 4 julia --project examples/basic_example.jl

Low-level interface

The complete SuperLUDIST C API is available in the generated modules `SuperLUDIST.SuperLUInt32andSuperLUDIST.SuperLU_Int64, with the shared enums inSuperLUDIST.Common. They are generated with Clang.jl, seegen/README.md` in the repository.
